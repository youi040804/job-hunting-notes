### LeetCode 1 两数之和（Hot100）

**所属算法模型：** 哈希表（空间换时间）

## 为什么想到？

题目要求找到两个数，使它们的和等于目标值 `target`。

如果使用暴力枚举，需要两层循环枚举所有数字组合。

由于需要不断查找"某个数字是否已经出现过"，因此可以考虑使用哈希表，将查找操作从 O(n) 优化到 O(1)。

## 核心思想

遍历数组中的每一个元素 `nums[i]`。

对于当前元素，计算：

```
need = target - nums[i]
```

然后在哈希表中查询：

```
need 是否已经出现？
```

如果已经存在：

直接返回这两个元素的下标。

如果不存在：

将当前元素及其下标存入哈希表。

整个过程只需要遍历一次数组。

## 为什么不能先全部放进哈希表？

如果先把所有元素全部存入哈希表，再进行查找。

可能会出现：

```
nums = [3,3]

target = 6
```

查找时容易把自己与自己匹配。

因此应采用：

> **一边遍历，一边查询，一边插入。**

这样能够保证匹配到的是之前已经遍历过的元素。

## 复杂度分析

**时间复杂度：** O(n)

数组仅遍历一次，哈希表查询平均为 O(1)。

**空间复杂度：** O(n)

最坏情况下需要将整个数组存入哈希表。

## 本次复盘收获

这道题最大的收获不是会写代码，而是理解了：

> **哈希表最大的价值就是用空间换时间。**

以后只要题目涉及：

- 快速查找
- 判断元素是否存在
- 查找某个值的位置

都应该优先考虑哈希表。
### LeetCode 242 有效的字母异位词

**所属算法模型：** 哈希统计（数组实现）
### 为什么想到？

题目要求判断两个字符串是否由相同字符组成，并且每个字符出现的次数完全一致。

这类问题的本质不是比较字符串，而是**比较每个字符出现的频率**。

由于题目说明字符串仅由 **26 个小写英文字母**组成，因此可以使用长度为 26 的数组记录每个字符出现的次数，而无需使用哈希表。

### 核心思想

维护一个长度为 26 的计数数组。

首先遍历字符串 `s`：

- 每遇到一个字符，对应位置计数加一

随后遍历字符串 `t`：

- 每遇到一个字符，对应位置计数减一

最后遍历整个计数数组：

- 如果所有位置都为 0，说明两个字符串中每个字符出现次数完全一致，返回 `true`
- 如果存在任意一个位置不为 0，则说明字符数量不同，返回 `false`

本质上就是：

> **统计字符频率，并比较两个字符串的频率是否完全一致。**

### 为什么不用 `unordered_map`？

虽然使用 `unordered_map<char, int>` 也能够完成统计，但题目已经限定：

- 字符仅包含 `'a' ~ 'z'`
- 总共只有 26 个字符

因此没有必要使用哈希表。
直接使用：

```
int cnt[26] = {0};
```

即可完成统计。

这种实现更加简单，同时空间复杂度也更低。

### 复杂度分析

**时间复杂度：O(n)**

遍历两个字符串各一次，最后遍历长度为 26 的数组一次。

由于 26 为常数，因此总体时间复杂度仍为 **O(n)**。

**空间复杂度：O(1)**

虽然申请了一个长度为 26 的数组，但数组大小是固定常数，不会随着输入规模增加，因此额外空间复杂度为 **O(1)**。

### 本次复盘收获

之前只知道可以利用哈希统计字符出现次数。

重新复盘后发现，这道题由于字符集固定，仅包含 26 个小写字母，因此可以进一步优化实现，使用固定长度数组代替 `unordered_map`，将空间复杂度优化为 **O(1)**。

以后遇到类似问题时，应先观察题目是否限定了字符集大小：

- 如果字符集固定（如 26 个小写字母、128 个 ASCII 字符），优先使用数组统计。
- 如果字符种类未知或范围较大，再考虑使用哈希表。

### LeetCode 283 移动零

**所属算法模型：** 双指针（快慢指针 / 原地覆盖）

#### 为什么想到？

题目要求：

- 在原数组上进行操作（原地修改）。
- 尽量减少额外空间。
- 保持非零元素的相对顺序。

由于不能创建新的数组，因此应该考虑使用两个下标在原数组上完成操作。快指针负责遍历整个数组，慢指针负责维护下一个非零元素应该放置的位置。

#### 核心思想

维护一个"有效区间"。

遍历数组时：

- 快指针负责扫描整个数组，寻找非零元素。
- 每找到一个非零元素，就将其覆盖到慢指针位置，并让慢指针向后移动一位。

所有非零元素处理完成后，再将慢指针之后的位置统一填充为 0。
 fill(nums.begin()+stack_size,nums.end(),0);
 
本质上就是：

> **将所有非零元素稳定地压缩到数组前面，再统一补零。**

#### 复杂度分析

- 时间复杂度：O(n)

每个元素最多访问一次，因此时间复杂度为 O(n)。

- 空间复杂度：O(1)

没有申请新的数组，仅使用了几个辅助变量，因此额外空间复杂度为 O(1)。

#### 本次复盘收获

之前一直把这种做法理解成"原地栈"。

重新思考后发现，这里并没有利用栈的后进先出（LIFO）性质，也没有 push、pop 等操作，因此称为"栈思想"并不准确。

更准确的理解应该是：

> **快慢指针维护有效区间（写指针 / 原地覆盖）。**

以后遇到原地修改数组的问题，应优先考虑快慢指针，而不是"栈"。
### LeetCode 125 验证回文串

**所属算法模型：** 双指针（对撞指针）

#### 为什么想到？

回文串具有天然的左右对称性。

因此可以分别从字符串两端开始，同时向中间比较字符是否相同。

#### 核心思想

首先对字符串进行预处理：

- 删除所有非字母数字字符（`isalnum()`）。
- 将所有字符统一转换为小写（`tolower()`）。

随后：

- 左指针从字符串开头开始。
- 右指针从字符串末尾开始。

如果两个字符相同，则继续向中间移动；否则直接返回 `false`。

当左右指针相遇或交错（`left >= right`）时，说明整个字符串满足回文性质。

#### 复杂度分析

当前实现：

- 时间复杂度：O(n)

字符串最多遍历两次（预处理一次，双指针比较一次），总体仍为 O(n)。

- 空间复杂度：O(n)

由于创建了新的字符串 `t` 存储预处理后的结果，因此额外空间复杂度为 O(n)。

#### 本次复盘收获

之前只关注了双指针比较过程，没有分析空间复杂度。

实际上，由于构造了新的字符串，当前写法的空间复杂度并不是 O(1)，而是 O(n)。

更优的做法是在原字符串上直接使用双指针：

- 左指针跳过非字母数字字符。
- 右指针同样跳过非字母数字字符。
- 不创建新的字符串。

这样可以将额外空间复杂度优化到 **O(1)**。

## LeetCode 392 判断子序列

### 算法模型

双指针-序列匹配模型

### 为什么想到？

题目要求判断 s 是否是 t 的子序列。

观察发现：

- 两个字符串都需要从前往后遍历；
- s 中字符的相对顺序不能改变；
- t 中没有匹配到当前字符时，只需要继续向后寻找，不需要回头。

因此想到使用两个指针：

- 一个指针维护 s 当前匹配位置；
- 一个指针遍历 t，寻找对应字符。

### 核心思路

使用两个指针：

- i 指向 s，表示当前匹配到的位置；
- j 遍历 t，负责寻找匹配字符。

如果：

```
s[i] == t[j]
```

说明找到一个字符：

```
i++;
j++;
```

否则：只移动 j，继续寻找。
### 复杂度

时间复杂度：O(n)

空间复杂度：O(1)
### 易错点

- 注意 `==` 判断，不要写成赋值 `=`
- 空字符串一定是任何字符串的子序列
## LeetCode 53 最大子数组和

### 算法模型

动态规划-最大连续子数组模型

### 为什么想到？

题目要求寻找**连续子数组的最大和**。

观察发现：

- 子数组必须连续，不能使用排序或者哈希等方法；
- 当前元素是否加入前面的结果，只取决于之前的最优状态；
- 每个位置都可以看作一个阶段，因此考虑动态规划。

进一步分析：
当前位置有两种选择：
1. 接在之前的最大连续子数组后面；
2. 从当前位置重新开始。
因此得到状态转移。
### 核心思路

定义：

```
dp[i] = 以 nums[i] 结尾的最大连续子数组和
```

状态转移：

```
dp[i]=max(dp[i-1]+nums[i], nums[i])
```

最终答案：

```
max(dp)
```

### 复杂度

普通 DP：

时间复杂度：O(n)

空间复杂度：O(n)

优化后：

由于 dp[i] 只依赖 dp[i-1]：

时间复杂度：O(n)

空间复杂度：O(1)

### 易错点

dp[i] 表示：

> 以当前位置结尾的最大连续和

不是：

> 前 i 个元素中的最大值。

## LeetCode 189 轮转数组

### 算法模型

数组翻转技巧模型

### 为什么想到？

最开始想到模拟移动：

每次把最后一个元素移动到最前面。

但是发现：如果移动 k 次，每次需要遍历整个数组，时间复杂度为：

```
O(n*k)
```

当 k 较大时效率很低。

进一步观察数组旋转后的结构：

原数组可以分成两部分：

```
后 k 个元素 + 前 n-k 个元素
```

目标是交换两部分的位置。

而翻转操作可以在 O(n) 时间内调整数组顺序，因此想到三次翻转。

### 核心思路

例如：

```
[1,2,3,4,5,6,7], k=3
```

步骤：

1. 整体翻转

```
[7,6,5,4,3,2,1]
```

2. 翻转前 k 个元素

```
[5,6,7,4,3,2,1]
```

3. 翻转剩余元素

```
[5,6,7,1,2,3,4]
```

### 复杂度

时间复杂度：O(n)

空间复杂度：O(1)
### 易错点

先处理：
```
k %= nums.size();
```

避免 k 超过数组长度。

```
void rotate(vector<int>& nums, int k) {
        k %= nums.size(); // 轮转 k 次等同于轮转 k % n 次
        ranges::reverse(nums);
        reverse(nums.begin(), nums.begin() + k);
        reverse(nums.begin() + k, nums.end());
}
```

## 题1：160. 相交链表

### 类型

链表 + 双指针。

### 为什么想到？

两条链表前缀长度可能不同，但相交后的尾部完全相同。让两个指针分别走完“自己的链表 + 对方的链表”，就能抵消长度差。

### 流程

- p 从 headA 出发，走到末尾后切到 headB；
- q 从 headB 出发，走到末尾后切到 headA；
- 两指针相等时返回该节点；不相交时会同时为 `nullptr`。

### 复杂度

时间：O(m+n)

空间：O(1)

代码：
```
ListNode*p=headA; 
ListNode*q=headB; 
while(p!=q){ 
	p=p?p->next:headB; 
	q=q?q->next:headA; 
} 
return p
```

## 题2：206. 反转链表

### 类型

链表指针操作。

### 为什么想到？

修改 `cur->next` 前，必须先保存原本的下一个节点，否则后半段链表会丢失。

### 流程

- `pre` 初始化为 `nullptr`，`cur` 初始化为 `head`；
- 保存 `cur->next`；
- 让 `cur->next` 指向 `pre`；
- `pre`、`cur` 同步后移；
- 循环结束后返回 `pre`。

### 复杂度

时间：O(n)

空间：O(1)

代码：
```
ListNode*cur=head,*pre=nullptr; 
while(cur!=nullptr){ 
	ListNode*temp=cur->next; 
	cur->next=pre; 
	pre=cur; 
	cur=temp; 
}
return pre;
```
