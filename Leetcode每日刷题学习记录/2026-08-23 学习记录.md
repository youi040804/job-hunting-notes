### 1. 946. 验证栈序列

这题不需要设计复杂算法，核心就是：

> 用一个辅助栈，把题目给出的入栈和出栈过程真实模拟一遍。

按照 `pushed` 顺序依次入栈：

```cpp
for (int x : pushed) {
    st.push(x);
}
```

同时维护一个指针：

```cpp
int j = 0;
```

表示：

> 当前 `popped[j]` 是下一个希望被弹出的元素。

每次入栈之后，只要满足：

```cpp
st.top() == popped[j]
```

说明当前栈顶正好就是希望出栈的元素，于是立刻弹出：

```cpp
st.pop();
j++;
```

而且这里必须使用：

```cpp
while
```

而不是：

```cpp
if
```

因为一次新的入栈操作之后，可能会连续触发多次出栈。

例如：

```text
pushed = [1,2,3,4,5]
popped = [4,5,3,2,1]
```

前面压入：

```text
1
2
3
4
```

遇到 `4` 后：

```text
pop 4
```

然后继续压入 `5`。

此时：

```text
push 5
↓
pop 5
↓
pop 3
↓
pop 2
↓
pop 1
```

所以一次 `push` 后可能连续匹配多个 `popped` 元素，这也是必须使用 `while` 的原因。

完整代码：

```cpp
class Solution {
public:
    bool validateStackSequences(vector<int>& pushed, vector<int>& popped){
        stack<int> st;
        int j = 0;

        for (int x : pushed) {
            st.push(x);

            while (!st.empty() &&
                   j < popped.size() &&
                   st.top() == popped[j]) {

                st.pop();
                j++;
            }
        }

        return j == popped.size();
    }
};
```

最后如果：

```cpp
j == popped.size()
```

说明 `popped` 中所有元素都已经按照合法的栈顺序成功匹配，因此返回 `true`。

如果最后仍然有元素无法匹配，说明这个弹出顺序不合法。

例如：

```text
pushed = [1,2,3,4,5]
popped = [4,3,5,1,2]
```

模拟到最后可能得到：

```text
栈：[1,2]
```

但下一个要求弹出的元素是：

```text
1
```

此时：

```text
2
```

压在 `1` 上面。

由于栈只能从栈顶弹出，所以不可能先弹出 `1`，因此这个序列不合法。

这题可以总结成一个比较通用的思路：

> 如果题目给出一种数据结构的操作序列，并要求判断某个结果是否合法，可以先考虑直接模拟这个数据结构本身。

本题就是典型的栈模拟。

时间复杂度 `O(n)`。虽然存在 `for + while`，但每个元素最多入栈一次、出栈一次，因此总操作次数仍然是线性的。

空间复杂度 `O(n)`，最坏情况下所有元素都会暂时保存在辅助栈中。


## 今日小结

- 验证栈序列本质上是一道数据结构模拟题，不需要为了“看起来像算法题”强行寻找复杂技巧。
- 遇到“给定操作顺序，判断某种数据结构能否产生目标结果”的问题，可以优先尝试直接模拟。
- 栈模拟中，要始终围绕栈的 LIFO 性质判断是否合法：被压在下面的元素不可能越过栈顶先弹出。
- `while` 和 `if` 的区别值得特别注意：一次操作可能连续触发多个合法出栈，因此必须一直检查新的栈顶。
