### 1. 删除有序数组中的重复项

#### 题目模型

给定一个非递减排序数组，要求：

- 原地删除重复元素；
    
- 保留元素相对顺序；
    
- 使用 O(1) 额外空间；
    
- 返回去重后的数组长度。
    

#### 解题思路

因为数组已经有序，所以相同元素一定连续出现。

由于要求原地修改，不能创建新的数组，因此考虑双指针：

- fast 指针负责遍历数组，寻找新的不重复元素；
    
- slow 指针维护已经去重完成的结果区域。
    

当：

```cpp
nums[fast] != nums[slow]
```

说明 fast 找到了新的元素。

此时：

```cpp
slow++;
nums[slow] = nums[fast];
```

将新元素加入结果区域。

遍历结束后：

```cpp
return slow + 1;
```

即为有效数组长度。

#### 核心代码

```cpp
class Solution {
public:
    int removeDuplicates(vector<int>& nums) {
        int slow = 0;

        for (int fast = 1; fast < nums.size(); fast++) {
            if (nums[fast] != nums[slow]) {
                slow++;
                nums[slow] = nums[fast];
            }
        }

        return slow + 1;
    }
};
```

#### 复杂度分析

时间复杂度：O(n)

fast 指针遍历整个数组一次。

空间复杂度：O(1)

只使用 slow 和 fast 两个变量。

### 2. 删除有序数组中的重复项 II

#### 题目模型

给定一个非递减排序数组：

- 原地删除重复元素；
    
- 每个元素最多出现两次；
    
- 保持相对顺序；
    
- O(1) 空间。
    

#### 初始思路问题

一开始尝试根据原数组中重复关系判断：

例如：

- 当前元素是否等于前一个元素；
    
- 是否需要移动 slow。
    

这种思路容易混乱。

原因：删除类双指针的核心不是判断原数组关系，而是维护：

> 已经构造完成的合法结果区域。

#### 正确模型

维护：

```text
[0, curr_size)
```

范围内的数据一定满足题目要求。

因为每个元素最多出现两次：

- 前两个元素一定合法；
    
- 从第三个元素开始判断。
    

判断条件：

```cpp
nums[i] != nums[curr_size - 2]
```

含义：

如果当前元素等于结果**数组倒数第二个元素**，说明它已经出现两次，再加入会变成第三次，因此跳过。

否则加入：

```cpp
nums[curr_size++] = nums[i];
```

#### 核心代码

```cpp
class Solution {
public:
    int removeDuplicates(vector<int>& nums) {
	    int n=nums.size();
        int curr_size = 2;

        for (int i = 2; i < n; i++) {
            if (nums[i] != nums[curr_size - 2]) {
                nums[curr_size++] = nums[i];
            }
        }

    return min(n,curr_size);//为了兼容数组长度为1的情况
    }
};
```

#### 复杂度分析

时间复杂度：O(n)

遍历数组一次。

空间复杂度：O(1)

原地修改。

## 今日算法总结

今天学习了有序数组删除类双指针：

核心思想：

> fast 负责探索原数组，slow 负责维护满足条件的结果区域。

区别：

### 保留一个重复元素

判断：

```cpp
nums[fast] != nums[slow]
```

### 保留两个重复元素

判断：

```cpp
nums[fast] != nums[slow - 1]
```

（等价于 curr_size - 2）

本质：
检查新元素加入后，是否违反限制。

## 今日收获

双指针并不是固定模板：

不能只记：

“快指针遍历，慢指针修改”。

更重要的是理解：

> slow 指针代表当前已经构造完成的答案状态。

之后遇到原地修改、删除元素、限制出现次数的问题，应优先考虑维护一个合法结果区域。
