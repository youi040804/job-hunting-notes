### 题1：138. 随机链表的复制

![](../Images/Pasted%20image%2020260818201033.png)
### 思路

不会，直接看题解。

这题考察的是**复杂链表的深拷贝**。

普通链表只有 `next` 指针，复制时只需要按照顺序创建节点即可；但是随机链表除了 `next` 外，还有一个 `random` 指针，它可能指向任意节点。

因此问题变成：

> 创建新节点时，如何找到原节点对应的新节点？

所以需要使用哈希表记录：

旧节点 -> 新节点

第一遍遍历：

- 创建所有新节点；
- 建立旧节点和新节点的映射关系。

第二遍遍历：

- 根据哈希表恢复新节点之间的 `next` 和 `random` 关系。

例如：

map[旧节点A] = 新节点A

map[旧节点B] = 新节点B

那么：

mp[cur]->next=mp[cur->next];
mp[cur]->random=mp[cur->random];

即可找到对应的新节点。

核心：

> 遇到对象之间存在任意引用关系的复制问题，不要直接复制指针，而应该先建立“旧对象 → 新对象”的映射，再恢复引用关系。

复杂度：

时间：O(n)

空间：O(n)

### 题2：148. 排序链表

![](../Images/Pasted%20image%2020260818201649.png)
### 思路

第一次想到：

> 遍历链表，把所有元素放入 multiset，然后重新构造链表。

这个方法可以实现排序，但是没有利用链表本身的特点。

这道题真正考察的是：

> 链表如何进行 O(nlogn) 排序。

链表不适合快速排序，因为无法随机访问；而归并排序天然适合链表。

整体流程：

排序链表=拆分链表+递归排序+合并有序链表

具体步骤：

1. 快慢指针找到链表中点。

slow 一次走一步

fast 一次走两步

当 `fast` 到达末尾时，`slow` 位于中间。

**连续数组寻找中间位置是mid=left+(right-left)/2**

2. 断开链表：

例如：

1 -> 2 -> 3 -> 4

拆成：

1 -> 2

3 -> 4

3. 递归排序两个子链表。

递归本质：

> 当前问题无法解决，就继续把更小规模的问题交给同一个函数处理。

4. 合并两个有序链表。

复用：

21. 合并两个有序链表

的双指针模板。

复杂度：

时间：O(nlogn)

空间：递归版本：O(logn)

代码：
```
ListNode* middleNode(ListNode*head);
ListNode* mergeTwoLists(ListNode*head1,ListNode*head2);

ListNode* sortList(ListNode* head) {

	if(head==nullptr||head->next==nullptr){
		return head;
	}

	ListNode*head1=head;
	ListNode*head2=middleNode(head);

	head1=sortList(head);
	head2=sortList(head2);

	return mergeTwoLists(head1,head2);
}
```


### 题3：146. LRU缓存机制

![](../Images/Pasted%20image%2020260818201823.png)
### 思路

不会，直接看题解。

题目要求：

- `get`
- `put`

平均时间复杂度：

O(1)

因此单独的数据结构无法同时满足：

- 快速查找 key；
- 快速维护访问顺序。

所以需要两个结构结合：

unordered_map + 双向链表

其中：
unordered_map负责：

key -> 节点地址

提供 O(1) 查找。


双向链表负责：维护访问顺序。

规则：

- 最近访问的节点放在链表头部；
- 最久没有访问的节点位于尾部。

因此：

get：

1. 哈希表找到节点；
2. 删除节点当前位置；
3. 移动到链表头部。

put：

如果 key 存在：

1. 修改 value；
2. 移动到头部。

如果 key 不存在：

1. 创建新节点；
2. 插入头部；
3. 如果超过容量，删除尾部节点。

核心：

> 哈希表负责快速定位，链表负责快速调整顺序。

复杂度：

时间：

get：O(1)

put：O(1)

空间：O(capacity)
