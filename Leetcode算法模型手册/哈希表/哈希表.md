## 一、模型特点

### 什么时候想到？

当题目出现以下特征时，可以优先考虑哈希表：

- 需要快速判断某个元素是否存在。
- 需要统计元素出现次数。
- 需要建立元素与其他信息之间的映射关系。
- 暴力方法需要频繁查找，导致时间复杂度过高。

核心关键词：

> **查找、判断存在、统计次数、建立映射 → 哈希表**

## 二、核心思想

利用哈希表保存已经遍历过的信息，使后续查询从线性搜索：```O(n)```

降低到平均：```O(1)```

常用数据结构：

```
unordered_map
unordered_set
```

如果元素范围固定，也可以使用数组作为哈希表。

例如：```int count[26];```
# 代表题①：两数之和（Two Sum）⭐⭐⭐

## 为什么想到？

题目要求找到两个数字，使：

```
nums[i] + nums[j] = target
```

转换思维：寻找：

```
target - nums[i]
```

是否已经出现。

如果使用暴力方法，需要枚举两个数字,时间复杂度：

```
O(n²)
```

而哈希表可以快速判断目标数字是否存在。

因此想到：

> 利用哈希表保存已经遍历过的数字，实现快速查询。
## 核心思想
将正向查找：```nums[i] + nums[j] = target```

转换为反向查找：```target - nums[i] 是否存在```

## 算法流程

1. 创建哈希表，保存已经遍历过的数字及其下标。
2. 遍历数组中的每个元素 `nums[i]`。
3. 计算当前元素需要寻找的数字：
```
target - nums[i]
```
4. 查询哈希表中是否存在该数字。
5. 如果存在，返回两个数字的下标。
6. 如果不存在，将当前数字加入哈希表。
## 复杂度
时间复杂度：```O(n)```
空间复杂度：```O(n)```

## 易错点

### 1. 先查询，再插入

错误：
```
先插入当前数字
再查询
```

可能导致：当前数字和自己匹配。

正确：

```
查询 target-num
↓
不存在
↓
插入当前num
```

### 2. 无序数组不能使用双指针

普通两数之和：

```
unordered array
```

不能直接双指针。因为左右移动没有规律。

只有排序数组才考虑双指针。

## 面试表达

如果面试官问：

> 为什么不用暴力？

回答：
因为暴力需要枚举两个数字，时间复杂度为 O(n²)。
通过哈希表保存已经访问过的元素，可以在遍历过程中快速判断目标元素是否存在，将时间复杂度降低到 O(n)。

# 代表题②：有效的字母异位词（Valid Anagram）⭐⭐⭐

## 为什么想到？

题目要求判断两个字符串是否由相同字符组成。

本质问题：

> 比较两个字符串中每个字符出现次数是否一致。

因此想到：统计每个字符出现次数。

## 核心思想

将字符映射到固定范围的数组中：

例如：

```
a → 0
b → 1
...
z → 25
```
通过计数数组记录每个字符出现次数。
由于题目限定：
- 只有小写字母
- 共26个字符
因此使用数组：
```
int count[26];
```
比哈希表更加简单高效。

## 算法流程

1. 创建长度为26的计数数组。
2. 遍历字符串 `s`：

对应字符数量：
```
count[c-'a']++
```
3. 遍历字符串 `t`：
对应字符数量：
```
count[c-'a']--
```
4. 遍历计数数组。
如果存在：
```
count[i] != 0
```
说明两个字符串字符数量不同。
返回：```false```
否则返回：true
## 复杂度

时间复杂度：```O(n)```
空间复杂度：```O(1)```
原因：
计数数组大小固定：26

## 易错点

### 1. 字符映射

正确：c-'a'
错误：'c'-65
原因：`c` 是变量，不是字符。

### 2. 哈希表和数组的选择

如果字符范围未知：

例如：
- 大小写字母
- 数字
- 特殊字符
可以使用：
```
unordered_map
```
如果范围固定：
例如：26个小写字母。
优先：数组计数

## 面试表达

如果面试官问：

> 为什么不用哈希表？

回答：因为题目限制字符范围固定，只有26个小写字母，因此使用数组模拟哈希表即可，空间固定且效率更高。

# 哈希表模型总结

> 用空间换时间，通过额外的数据结构降低查询成本。
