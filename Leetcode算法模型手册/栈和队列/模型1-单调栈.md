### 适用场景

当题目出现：

- 下一个更大元素
- 下一个更小元素
- 右边第一个比当前元素大的位置
- 左边第一个比当前元素大的位置
- 等多久以后出现更大值

需要考虑单调栈。

### 核心思想

栈中保存：

```
还没有找到答案的元素
```

当新的元素到来以后，如果它能够解决栈顶元素，就不断弹栈并结算答案。

### 常见写法

如果题目需要计算距离，栈中通常保存：

```
下标
```

而不是元素值。

例如寻找右侧第一个更大元素：

```
stack<int> stk;

for (int i = 0; i < nums.size(); i++) {

    while (!stk.empty() &&
           nums[i] > nums[stk.top()]) {

        int index = stk.top();
        stk.pop();

        // 当前 i 就是 index 等到的答案
    }

    stk.push(i);
}
```

### 思维模型

不要让每一个旧元素：

> 主动向右寻找答案。

而是反过来：

> 当前新元素到来时，帮助之前还在等待答案的元素完成结算。

### 为什么是 O(n)

虽然代码中存在：

```
for + while
```

但每个元素最多：

```
入栈一次
出栈一次
```

所以总复杂度仍然是：

```
O(n)
```
