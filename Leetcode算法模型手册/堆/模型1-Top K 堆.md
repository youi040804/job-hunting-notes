### 适用场景

当题目出现：

- 第 K 大 / 第 K 小
- 前 K 大 / 前 K 小
- 数据量较大，不希望完整排序

可以考虑维护一个**大小最多为 K 的堆**。

### 核心思想

Top K 问题的关键不是：

> “我要找最大的，所以就用大顶堆。”

而是：

> **我想始终保留 K 个候选元素，并且能够快速淘汰当前候选中最不合格的那个。**

因此：

```text
前 K 大
→ 需要淘汰候选中最小的元素
→ 使用小顶堆

前 K 小
→ 需要淘汰候选中最大的元素
→ 使用大顶堆
```

可以直接记成：

```text
前 K 大 → 小顶堆
前 K 小 → 大顶堆
```

### 一、前 K 大：大小为 K 的小顶堆

目标是始终保存：

```text
当前见过的最大的 K 个元素
```

由于一旦候选数量超过 K，就要淘汰其中最小的元素，因此使用小顶堆。

```cpp
priority_queue<int, vector<int>, greater<int>> pq;

for (int x : nums) {
    pq.push(x);

    if (pq.size() > k) {
        pq.pop();
    }
}
```

小顶堆的：

```cpp
pq.top()
```

始终是当前候选集合中的最小值。

遍历结束后，堆中保存的就是整个数组中最大的 K 个元素，而这 K 个元素中最小的那个，正好就是：

```text
第 K 大
```

因此如果题目只要求第 K 大：

```cpp
return pq.top();
```

例如：

```text
nums = [3,2,1,5,6,4]
k = 3
```

最终堆中留下：

```text
[4,5,6]
```

其中最小的 `4` 就是第 3 大。

### 二、前 K 小：大小为 K 的大顶堆

目标变成：

```text
始终保存当前见过的最小 K 个元素
```

此时如果出现更小的元素，就需要淘汰当前候选中最大的那个，因此使用大顶堆。

```cpp
priority_queue<int>pq;

for(int x:nums){
	pq.push(x);
	if(pq.size()>k){
		pq.pop();
	}
}

```

大顶堆的：

```cpp
pq.top()
```

始终是当前 K 个最小候选中最大的那个。

所以当新元素：

```text
x >= pq.top()
```

说明它连当前的第 K 小都比不过，不需要加入。

而当：

```text
x < pq.top()
```

说明它应该进入前 K 小，因此淘汰原来最大的候选：

```cpp
pq.pop();
pq.push(x);
```

遍历结束后，堆中就是整个数组最小的 K 个元素。

### 为什么方向是“反的”

这个地方最容易绕。

```text
找前 K 大
```

并不是因为“大”就使用大顶堆，而是因为我们已经有 K 个候选以后，希望快速找到：

```text
最应该被淘汰的最小值
```

所以需要小顶堆。

同理：

```text
找前 K 小
```

需要快速找到候选中的最大值并淘汰，因此使用大顶堆。

真正应该记的是：

```text
保留前 K 大 → 淘汰最小 → 小顶堆
保留前 K 小 → 淘汰最大 → 大顶堆
```

### C++ 常用写法

大顶堆：

```cpp
priority_queue<int> pq;
```

小顶堆：

```cpp
priority_queue<int, vector<int>, greater<int>> pq;
```

### 复杂度

堆中最多只维护 K 个元素。

单次 `push / pop`：

```text
O(log K)
```

**堆的插入和删除“修改元素本身”通常很快，真正花时间的是为了重新满足堆性质而进行的上浮或下沉，因此整体都是 `O(log K)`。**

遍历 N 个元素：

```text
O(N log K)
```

额外空间：

```text
O(K)
```

相比完整排序的：

```text
O(N log N)
```

当 `K` 明显小于 `N` 时，Top K 堆通常更加合适。
